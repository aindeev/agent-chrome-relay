No “Allow remote debugging?”

No debugging port at all. A small MV3 extension runs DevTools commands through chrome.debugger, so Chrome never asks. (It does show its “started debugging this browser” bar while agents work.)

Sign-ins: hands-off, never credentials

When a site bounces through Google and the right account is already signed in, the extension clicks the account and Continue for the agent. Agents never type credentials: a password, passkey or 2-step screen stops the hop and the agent asks you to sign in in your own window.

Popups stay hidden

Popups and “open in new tab” links become new hidden tabs owned by the same agent. Popup sign-in flows that report back to their opener keep working.

1Password-friendly

Chrome drops an extension’s debugger from pages that contain another extension’s frame, like 1Password’s menu on login forms. The agent’s commands wait while the extension re-attaches.

Cleans up after itself

Tabs of an agent that has been silent for 30 minutes are closed. Your own tabs and tab groups are never touched.

How it works

Three small pieces, one hop each

  1. CLI agent-browser your agent runs it in a shell
  2. ws
  3. background service relay 127.0.0.1:9333
  4. ws
  5. MV3 extension Chrome Relay one per Chrome profile
  6. chrome.debugger
  7. background agent tab inactive, in “Agents”

The relay

A local DevTools endpoint per agent. Each agent sees and controls only the tabs it opened; anything that would raise or focus the browser is swallowed.

The extension

Opens each agent tab inactive in a collapsed “Agents” group and runs DevTools commands in it via chrome.debugger. No remote-debugging port.

The CLI

chrome-relay does setup, prints the connection URL for a profile, checks everything with doctor and reads the audit trail.

Security

Who gets to drive your browser

  • A per-machine secret

    Generated at setup and stored readable only by you. It is embedded in the URL that chrome-relay url prints.

  • Only agent apps

    The connecting process must come from Claude Code, Codex, Cursor or Paseo. The relay looks the process up and checks the markers those apps set, then its parents.

  • Only your extension

    The extension side must be this checkout’s extension, checked by its chrome-extension:// origin, and the connecting process must be Chrome.

  • Web pages are refused

    Any connection carrying a web page’s origin is turned away, even with the secret.

Being honest

What it is not

These checks keep other local tools, web pages and accidents out. They are not a boundary against malware already running as you, which could read the secret and fake the markers.

It is opt-in, too: nothing installs the extension for you, and it only runs on Macs whose owner set it up.

Audit trail

Every agent action, written down

One log file per day: who connected, pages, clicks, special keys, the agent’s own scripts, screenshots, popups and sign-in clicks. Typed text is stored only as a length, and URLs lose their query string.

Install

Set up once, about two minutes

Needs macOS, Google Chrome, Node.js 20+ and agent-browser.

  1. 01

    Get agent-browser

  2. 02

    Clone and run setup

    Creates the secret and the background service, finds your profiles, puts chrome-relay on your PATH and links the Claude Code skill. Safe to re-run.

  3. 03

    Load the extension in each profile

    chrome://extensionsDeveloper modeLoad unpackedextension/

    Do it in every Chrome profile your agents should use, then check with chrome-relay doctor.

Commands

  • $ chrome-relay setupone-time setup; safe to re-run
  • $ chrome-relay url [email]connection URL for agent-browser, for a profile
  • $ chrome-relay identitiesprofiles, their Google accounts, which account each site uses
  • $ chrome-relay statusconnected profiles and agents
  • $ chrome-relay doctorcheck everything and say how to fix it
  • $ chrome-relay updateafter git pull: restart the relay, reload the extension
  • $ chrome-relay auditthe latest audit events
  • $ chrome-relay logsthe latest relay log lines
  • $ chrome-relay uninstallremove the service, CLI link and skill

FAQ

How do my agents know to use it?

Setup links a skill into Claude Code, so every repo gets it. For Codex, Cursor and others, point them at the same skill file, for example with one line in your global agent instructions.

Will Chrome show anything while agents work?

Yes: Chrome shows its “Chrome Relay started debugging this browser” bar. You will not see the “Allow remote debugging?” dialog, because no debugging port is opened.

Can an agent sign in for me?

No. It can click through a Google account chooser when the right account is already signed in. Anything that needs a password, passkey or 2-step code stops, and the agent asks you to sign in in your own window.

Does it work on Windows or Linux?

Not today. Setup installs a macOS background service, so it needs a Mac with Google Chrome.

How do I update or remove it?

After git pull, run chrome-relay update. To remove it, run chrome-relay uninstall and remove the extension in each profile.
