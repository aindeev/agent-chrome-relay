chrome relay

Let your AI agents use your Chrome, signed in as you, without interrupting you.

Your agents can check a dashboard, pull a report from a web app, fill in a form in an internal tool or review a staging site, in background tabs you never have to look at. Give them a goal and Chrome Relay carries it out in seconds, checking every step. When a site needs a login, they can sign in with the logins you keep in 1Password, without ever seeing a password, and you approve with Touch ID or Face ID. It runs on macOS with Google Chrome, and works today with Claude Code, Codex, Cursor and Paseo.

What it does

Your Chrome, your logins, your agents

Works with the agent you already use

Claude Code, Codex, Cursor and Paseo can all use it today. They drive Chrome through the open-source agent-browser tool, Chrome’s standard DevTools protocol and Chrome Relay’s own chrome-relay do. You are not tied to one AI company’s browser extension, and switching agents changes nothing. Several agents can work at once, and each one sees only its own tabs.

Runs fully in the background

Agent tabs open inactive, inside a collapsed “Agents” tab group. Your screen, your active tab and the app you are typing in don’t change while the agent works. Commands that would bring Chrome to the front are ignored. If an agent needs you, your Mac shows a notification, and clicking it opens that tab.

Uses the logins already in your Chrome

The agent works in the Chrome profile you pick by email, so it is already signed in wherever you are: Google Workspace, GitHub, your internal tools. It clicks through Google account pickers for accounts that are already signed in, and popups open as its own tabs. When a page asks for a password or 2-step code, it signs in on its own: from the 1Password vaults you share with it, or with the code the site emailed you. It asks you only when it has no way in.

One command for a whole goal

With chrome-relay do the agent states the goal once, with the values it knows and how to tell it’s done. Chrome Relay fills the fields the agent names, replays what worked on that site before, and asks a fast decision model for the rest. It checks every step before and after. Anything it isn’t sure of, or any delete, send or pay the goal didn’t ask for, goes back to the agent. How it works.

Signs in with 1Password, without seeing a password

If you turn it on, agents sign in with logins from the 1Password vaults you share with them: passwords, 2-step codes and passkeys. The agent names the item; Chrome Relay types the value, only on that item’s website, and hides it from everything the agent reads. New accounts and 2-step keys the agent sets up are saved to 1Password the same way. It works with 1Password only for now. Off until you set it up.

You approve, on your Mac or your iPhone

Each sign-in asks you first, naming the agent, the site and the account: Touch ID on your Mac, or Face ID on a paired iPhone when you’re away, whichever answers first. Passkeys Chrome Relay makes are kept in your Mac’s Secure Enclave and never leave it. The iPhone app, Chrome Relay Approve, is in App Store review; until it’s out you can build it from the repo with Xcode.

Fast: a whole form in about 2.5 seconds

Commands go straight to your open Chrome, about 0.15 s each, so the browser is never the slow part. What takes time is an agent thinking between clicks: about 3 seconds per action in our measurements. chrome-relay do removes most of that. In a real Chrome, with TypeSafe’s Jev deciding, a 7-step order form took 2.5 s, the same form replayed from a saved flow took 1.2 s, and finding a Wikipedia article through its search suggestions took 2.0 s. Without a Jev key it uses Claude Haiku through your own Claude Code, at 1 to 1.5 s per decision. The measurements, and how the models compare.

How it works

How a command reaches your Chrome

Your agent runs agent-browser commands, or hands over a whole goal with chrome-relay do. A small service on your Mac passes them to the Chrome Relay extension, which carries them out in the agent’s own tab.

  1. CLI agent-browser or chrome-relay do
  2. ws
  3. background service relay 127.0.0.1:9333
  4. ws
  5. MV3 extension Chrome Relay in each Chrome profile
  6. chrome.debugger
  7. background agent tab inactive, in “Agents”

The relay

One program that you build and sign on your own Mac, reachable only from your Mac. It gives each agent its own connection, shows it only the tabs it opened, and ignores commands that would bring Chrome to the front. It also talks to 1Password and your Mac’s Secure Enclave, if you turn that on, so no agent ever holds a password or a key.

The extension

You load it in each Chrome profile your agents may use: from your download today, from the Chrome Web Store once it’s through review. It opens agent tabs inactive in the collapsed “Agents” group and runs commands in them through Chrome’s chrome.debugger API, without opening a remote-debugging port.

The CLI

chrome-relay sets everything up, prints the connection URL for a profile, carries out goals with do, checks your install with doctor and shows the audit log.

Security

Who can connect to the relay

The relay checks every connection. Only Claude Code, Codex, Cursor and Paseo running on your Mac, with your Mac’s secret, get through.

  • A secret for this Mac

    Created during setup and readable only by your user account. It is part of the URL that chrome-relay url prints, so keep that URL private.

  • Only the four agent apps

    The connection must come from Claude Code, Codex, Cursor or Paseo. The relay looks up the connecting process and checks for the markers those apps set, in that process or its parents.

  • Only your copy of the extension

    On the Chrome side, the relay accepts only the extension you set up, identified by its chrome-extension:// origin, and only from the Chrome process.

  • Agents never hold your secrets

    With 1Password turned on, the relay types a login only into that item’s own website, and passwords only into password fields. What the agent reads back is masked. The 1Password token and passkey handles sit in your Keychain, readable only by the program you signed.

  • Web pages can’t connect

    A connection that comes from a web page is refused, even if it has the secret.

Limits

What these checks don’t cover

They keep out other programs, web pages and mistakes. They don’t protect against malware already running on your Mac as you, which could read the secret and fake the markers.

An agent you allow can use a login as intended: sign in to that site. So share with agents only the accounts you’re happy for them to use.

Nothing installs the extension for you. It only runs on a Mac where you set it up yourself.

Audit log

Everything your agents do is logged

Run chrome-relay audit to see it. The log records which agent connected, the pages it opened, its clicks, special keys, scripts, screenshots, popups, Google sign-in clicks, every step of a chrome-relay do run and every 1Password fill, in one file per day. Typed text is saved only as a character count, 1Password fills as the item and field (never the value), and query strings are removed from URLs.

Install

Set it up once per Mac

Today you build Chrome Relay from source, which takes about two minutes. You need macOS, Google Chrome, Go and agent-browser. For the full password experience (signing in with 1Password, passkeys in your Mac’s Secure Enclave, approving on your iPhone) you also need Xcode’s command line tools; all of that is optional.

Coming soon: the Chrome extension in the Chrome Web Store and the iPhone app, Chrome Relay Approve, in the App Store. Both are in review. Until they’re out, load the extension from your download and build the iPhone app from the repo, as below.

Easiest

Let your agent set it up

Paste this prompt into Claude Code, Codex or Cursor, in its auto mode (Claude Code: Shift+Tab, or claude --permission-mode auto; Codex: --full-auto) so it doesn’t stop for every command. The agent installs what’s missing, builds Chrome Relay, runs setup, sets up 1Password sign-ins and tells your other agents how to use it. You only load the extension and approve in 1Password.

Set up Chrome Relay on this Mac, so you and my other AI agents can use my signed-in Chrome from the command line, in background tabs.

Repo: https://github.com/aindeev/agent-chrome-relay (read its README first).

Do the whole setup yourself, start to finish, without stopping to ask me. Install what's missing, pick sensible defaults, fix what fails, and tell me what you chose at the end. Stop for me only at the steps marked ME, which only I can do, and do everything else while you wait.

1. Check the basics: macOS, Google Chrome, git, Go 1.25+, agent-browser and Xcode's command line tools (`xcode-select -p`). Install whatever is missing: `brew install go`, `npm i -g agent-browser`, `xcode-select --install` (the command line tools are what let agents sign in with 1Password and use passkeys, so install them).
2. Clone the repo to ~/agent-chrome-relay (if it's already there, `git pull` instead). In the clone, run `./build`: it compiles Chrome Relay and signs it on this Mac. If it lists several code-signing identities, pick one yourself (a Developer ID Application, else an Apple Development one) and run `./build --identity "<that name>"`. Then run `./chrome-relay setup`.
3. ME: loading the extension (Chrome lets only me do it). Copy the clone's `extension` folder path to my clipboard (`pbcopy`) and tell me, in one short list: in each Chrome profile agents should use, open chrome://extensions, turn on Developer mode, Load unpacked, press Cmd+Shift+G and paste the path, then pin Chrome Relay (puzzle-piece icon, then the pin). Meanwhile do steps 4 and 7, then check with `chrome-relay doctor` until it sees the extension.
4. Run `chrome-relay notify test`. ME: allow the notification macOS shows (it's only used when an agent is stuck on something only I can do).
5. Run `chrome-relay doctor` and fix whatever it reports until every line is ok. Then run `chrome-relay identities`: the defaults (each profile's own account) are fine; tell me what it found.
6. Smoke test with the default profile:
   agent-browser --cdp "$(chrome-relay url <email>)" open https://github.com
   agent-browser get title
   agent-browser close
7. Make sure all my agents know how to use it. Claude Code already has it: setup linked the chrome-relay skill. For Codex, Cursor or other agents I have, add a one-line note to their global instructions (for example ~/.codex/AGENTS.md) that points to <clone>/skill/SKILL.md for any browser step that needs my logins.
8. Signing in with 1Password: this is what lets agents sign in without me, so set it up if I have 1Password. `brew install 1password-cli`; if `op account list` fails, ME: turn on 1Password > Settings > Developer > "Integrate with 1Password CLI". Then, for each account `op account list` shows, run `chrome-relay vault setup "Shared with Chrome Relay (<short name>)" --account <email>` (1Password asks ME to approve; the token goes straight into the Keychain). Tell me to move or copy the logins agents may use into those vaults, and run `chrome-relay vault` to show me what agents can see.
9. `chrome-relay do` carries out a whole goal in one command; it decides with Claude Haiku through my Claude Code. Run `chrome-relay decider` and tell me what it says.

When you're done, tell me in a few lines what you set up and chose, and mention the extras I can turn on later: approving on my iPhone with Face ID (README, "Approving from your iPhone") and the faster Jev decider (`pbpaste | chrome-relay decider jev` with a TypeSafe key; I paste the key myself).

Rules while you do this:
- Never print, log or paste the URL from `chrome-relay url`. It contains this Mac's secret.
- Never ask me for a 1Password token, password or API key: those go straight from me into the Keychain.
- Never drive my Chrome any other way: no --auto-connect, no --cdp 9222, no --headed, no Playwright attached to it and no AppleScript.

The same prompt is at agent-chrome-relay.aindeev.com/setup-prompt.txt. To set it up by hand instead:

  1. 01

    Install agent-browser

  2. 02

    Clone, build and run setup

    ./build compiles Chrome Relay and signs it on your Mac: with your code-signing identity if you have one, otherwise ad-hoc. Without Xcode’s command line tools it builds the core only, without 1Password and Secure Enclave passkeys, and says so. Setup creates your Mac’s secret, starts the background service, finds your Chrome profiles, adds chrome-relay to your PATH and installs the Claude Code skill. It is safe to run again.

  3. 03

    Load the extension in each profile

    chrome://extensionsDeveloper modeLoad unpackedextension/

    Repeat this in every Chrome profile your agents should use, pin it so you see its badge, then run chrome-relay doctor to check. Once the Chrome Web Store version is through review, this step becomes one click.

  4. 04

    Optional: let agents sign in with 1Password

    It asks which 1Password accounts agents may use, then creates a shared vault and a service account that can open only that vault. Move in the logins agents may use. Needs the 1Password app and CLI, and the build with Xcode’s command line tools. 1Password is the only password manager supported for now.

  5. 05

    Optional: approve from your iPhone

    The iPhone app is in App Store review. For now, ./ios/build builds it with Xcode and installs it on your plugged-in iPhone. chrome-relay phone pair then shows a QR code to scan. After that, approvals go to Touch ID on the Mac and Face ID on the iPhone at once.

FAQ

Is there a Chrome Web Store extension or an iPhone app?

Both are in review and coming soon. For now you build from source: the extension is loaded from your download (chrome://extensions, Load unpacked), and the iPhone app, Chrome Relay Approve, is built from the repo with Xcode (./ios/build). The Mac service is always built and signed on your own Mac: that is what lets macOS tie its Keychain item to your signature.

Which password managers does it work with?

Only 1Password for now. Agents sign in with logins from the 1Password vaults you share with them: passwords, 2-step codes and passkeys. Other password managers are kept out of agent tabs so they don’t interfere, but agents can’t use them to sign in.

Can an agent sign in for me?

Yes, so a task doesn’t stop at a login page. If a Google account chooser shows an account that is already signed in, the extension picks it. If a page needs a password or 2-step code, the agent signs in with 1Password, and with codes the site sends to your email, which it reads and types itself; it asks you only when it has no way in. For 1Password, run chrome-relay vault setup: in the 1Password accounts you pick, Chrome Relay creates a shared vault for agents and a service account that can open only that vault. The agent fills a field with a reference like op://Shared with Chrome Relay/GitHub/password, and the relay types the value, only on that item's website. You approve with Touch ID on the Mac or, if you pair it, Face ID on your iPhone, and the prompt names the agent, the item and the site.

Can agents create accounts and turn on 2-step verification?

Yes, if 1Password is set up. Chrome Relay generates the password, or reads the 2-step setup key from the page, saves it to your shared 1Password vault after you approve, and types it. The agent sees neither. Chrome Relay never changes your own items: it only edits the ones it made.

How do passkeys work?

Passkeys that Chrome Relay creates for an account live in your Mac’s Secure Enclave and never leave it, and every sign-in needs your approval. Passkeys that only 1Password holds stay in 1Password: the request goes to 1Password’s own prompt in the agent’s tab, your Mac notifies you, and you approve it there. chrome-relay passkeys off turns passkeys in agent tabs off.

What is chrome-relay do, and which model does it use?

It carries out a whole goal in one command instead of one click at a time. Steps the agent’s data covers, and flows that worked before, need no model. For the rest it asks TypeSafe’s Jev (about 0.15 s per decision) if you saved a TypeSafe key with chrome-relay decider jev, otherwise Claude Haiku through your own Claude Code (1 to 1.5 s). The model sees a shortlist of the page’s controls, some of the page’s text and the values the agent gave, never a 1Password reference or what it holds. With Jev, that goes to TypeSafe. More on the approach.

Do I have to use 1Password, passkeys or the iPhone app?

No. Chrome Relay works without them: background tabs, your existing logins, Google account pickers, chrome-relay do and the audit trail are the core. Signing in with 1Password stays off until you run chrome-relay vault setup, and chrome-relay vault forget turns it off again. The iPhone app is only for approving when you’re away from the Mac.

How do my agents know to use it?

Setup installs a skill for Claude Code, so it knows how to use Chrome Relay everywhere. For Codex, Cursor and other agents, add one line to their global instructions that points to the same skill file. The setup prompt offers to do this for you.

Will Chrome show anything while agents work?

Yes. Chrome shows a “Chrome Relay started debugging this browser” bar while agents work. You won’t get an “Allow remote debugging?” dialog, because Chrome Relay doesn’t open a debugging port.

Does it work on Windows or Linux?

Not yet. Setup installs a macOS background service, so you need a Mac with Google Chrome.

How do I update or remove it?

To update, run git pull and ./build in your clone, then chrome-relay update. To remove it, run chrome-relay uninstall and remove the extension from each Chrome profile.
